# 한 달 기준 전략 재탐색 (4차, 2026-09-28)

재현: `python -m backtest.research4` (15초). 전체 표는 `research4_3y_20260923.md`.

## 먼저: 5년치는 아직 못 돌렸다

이 클라우드 환경의 네트워크 정책이 한투 API·한투 종목 마스터·네이버 금융·야후·KRX 를 전부 막는다.
그래서 5년치 데이터는 네 쪽(NCP 서버나 PC, 한투 키가 있는 곳)에서 받아야 한다. 명령은 준비해 뒀다 (맨 아래).
아래 결과는 기존 3.4년 스냅샷(2023-04 ~ 2026-09) 기준이다.

## 결론

1. **"한 달 +10%"짜리 전략이 나왔지만, 생존편향이 만든 숫자라 믿으면 안 된다.**
   KOSPI200+KOSDAQ150 에서 20일 수익률 상위 2종목을 매주 교체(시장 100일선 필터)하면
   한 달 평균 IS +10.0%, OOS +10.9%. 그런데 뜯어보면:
   - 거래의 82%가 KOSDAQ 종목이고, **이익은 상위 10건(제주반도체 +258%, 성호전자 +143%, 신성델타테크 +115% …)이 전부다.**
     그 10건을 빼면 나머지 86건은 합쳐서 손실(로그합 −2.07).
   - 백테스트 종목이 "지금의 KOSDAQ150 구성종목"이라, 급등한 뒤 살아남아 지수에 들어온 종목만 과거로 가서 산 셈이다.
     급등했다 무너진 수많은 테마주는 표본에 아예 없다.
   - 같은 규칙을 구성종목이 잘 안 바뀌는 KOSPI100 에서 돌리면 한 달 평균 +0.8%로 쪼그라든다.
2. **편향이 적은 KOSPI100 안에서는, 한 달 기준으로도 "그냥 보유"를 확실히 넘는 전략이 없다.**

| 전략 (KOSPI100, 2슬롯·30만원 이하) | 한 달 평균 IS / OOS | +10%↑ 달 IS / OOS | −10%↓ 달 IS / OOS |
|---|---|---|---|
| 동일가중 보유 (기준선, 60만원으론 불가) | +2.7% / +2.8% | 13% / 20% | 1% / 7% |
| **신고가 근접** (120일 최고가에 가장 가까운 2종목, 20일마다 교체) | **+3.3% / +2.7%** | 19% / 24% | 5% / 8% |
| 모멘텀 (60일 수익률 상위, 20일마다 교체) | +4.8% / +1.3% | 34% / 23% | 15% / 19% |
| 주도주 눌림 (2차 추천 ①) | +1.9% / +2.1% | 19% / 18% | 9% / 5% |
| 거래대금 급증 돌파 | +1.3% / −5.2% | 22% / 12% | 20% / 34% |

   - **신고가 근접**이 새로 찾은 것 중 가장 낫다. IS·OOS 가 비슷하고(+3.3% → +2.7%) 크게 잃는 달이 5~8%로 적다.
     George & Hwang(2004)의 "52주 신고가 근접" 효과를 데이터 길이 때문에 120일로 줄인 버전이다.
     다만 평균은 보유와 같은 수준이다. **"한 달 +10%"를 안정적으로 내는 대형주 전략은 이 데이터에 없다.**
   - 모멘텀은 IS 에서 제일 좋았지만(+4.8%) OOS 에서 +1.3%로 떨어졌다.
   - 거래대금 급증 돌파는 OOS 에서 무너졌다 (−5.2%).

## 정직한 기대치

- 대형주 기준 한 달 기대값은 전략과 무관하게 **+2 ~ +4%** 근처다. 이보다 큰 숫자는 대부분 소수의 대박 거래에서 나온다.
- 한 달 +10% 이상을 노리면 방법은 사실상 **소형·테마주 단기 모멘텀**뿐이다. 이게 실제로 통하는지는 편향 없는 데이터로만 판단할 수 있다.
  지금 데이터로는 "통한다"와 "생존편향이다"를 구별할 수 없다.
- 그래서 5년 · **전 종목(코스피·코스닥 보통주 약 2,500개)** 데이터가 필요하다.
  전 종목도 상장폐지 종목은 빠져서 편향이 조금 남지만, "지수에 새로 들어온 승자만 모은" 지금보다 훨씬 작다.
  2021-09 ~ 2023-09 구간(2022 하락장 포함)은 선택에 전혀 안 쓰고 홀드아웃 검증으로만 쓴다 (규칙을 데이터 받기 전에 고정했다).

## 5년 · 전 종목 데이터 받는 법

한투 키가 있는 곳(NCP 서버 `/opt/ma5-bot` 또는 PC)에서, **장 마감 뒤에** 이 브랜치를 받아서:

```bash
git fetch origin backtest-universe-iofw7v && git checkout backtest-universe-iofw7v
python -m backtest.run fetch --years 5 --all        # 약 3~5시간. 끊겨도 다시 돌리면 이어서 받는다
python -m backtest.run snapshot --out backtest/snapshot5y.json.gz
git add backtest/snapshot5y.json.gz && git commit -m "backtest: 5년 전 종목 스냅샷" && git push
```

- 실전 봇과 같은 앱키 유량을 나눠 쓰므로 장중엔 돌리지 않는다. 다음 날 08시 전에 끝나도록 저녁에 시작한다.
- 스냅샷은 기간 중 한 번도 20일 평균 거래대금 50억을 못 넘은 종목을 빼서 크기를 줄인다 (시뮬레이터가 어차피 안 사는 종목들). 예상 30~40MB.
- 또는 이 클라우드 환경 설정에서 `fchart.stock.naver.com` 과 `new.real.download.dws.co.kr` 를 허용해 주면 내가 네이버에서 직접 받을 수도 있다.
  (네이버는 한투와 수정주가 기준이 조금 다를 수 있다.)

스냅샷이 올라오면 `BT_SNAPSHOT=backtest/snapshot5y.json.gz python -m backtest.research4` 한 줄로 전 종목·5년·홀드아웃까지 돈다.
